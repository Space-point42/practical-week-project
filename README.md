# 知识管理系统

> 南京邮电大学 计算机学院 ·《专业课程设计II》题目一
> 指导教师：朱曼　｜　周期：2026.10.12 – 2026.10.23（第 7–8 周）

一个面向课程知识的管理平台：以**知识本体**组织内容的逻辑结构，以**全文检索与向量检索的混合召回**定位知识，以**检索增强生成（RAG）**回答自然语言提问，并提供带**版本管理**的内容管理系统。

## 一、快速开始

### 环境要求

| Maven | 3.8+ | 用于构建后端 |

### 三步启动

```bash
# 1) 初始化数据库（创建 kms 库与 20 张表）
#    Windows：
scripts\init-db.bat
#    Linux / macOS / Git Bash：
bash scripts/init-db.sh
#    如需指定账号：bash scripts/init-db.sh root 你的密码

# 2) 启动后端（首次启动会自动导入本体与演示数据，约 30 秒）
#    Windows：scripts\start-backend.bat
bash scripts/start-backend.sh

# 3) 启动前端（另开一个终端）
#    Windows：scripts\start-frontend.bat
bash scripts/start-frontend.sh
```

打开 <http://localhost:5173>，用下列账号登录（登录页可点击自动填入）：

| 用户名 | 口令 | 角色 | 权限范围 |
|---|---|---|---|
| `admin` | `admin123` | 管理员 | 全部功能，含用户管理、本体维护、版本策略、索引重建 |
| `editor` | `editor123` | 编辑 | 创建 / 编辑 / 提交 / 发布知识，管理版本 |
| `student` | `student123` | 浏览者 | 检索、浏览、下载、智能问答 |

> 后端接口文档：<http://localhost:8080/swagger-ui.html>

### 配置说明（本机密钥与口令）

数据库口令、大模型 API Key 这类本机配置统一放在
`backend/src/main/resources/application-local.yml`（已被 `.gitignore` 忽略），
后端启动时默认激活 `local` profile 自动加载它。

```yaml
kms:
  rag:
    chat:                 # 生成模型（智能问答的"作答"环节）
      provider: openai    # openai = 走 OpenAI 兼容接口；none = 离线抽取式
      openai:
        base-url: https://api.deepseek.com/v1
        api-key: sk-xxxxxxxx
        model: deepseek-flash
```

若要改用数据库口令，也可以在 `application-local.yml` 里覆盖 `spring.datasource.*`，
或者用环境变量启动：

```bash
KMS_DB_PASSWORD=你的口令 java -jar backend/target/kms.jar
```

> ⚠ **打包提交前请删除 `application-local.yml`**，或至少清空其中的密钥。
> 压缩包不受 `.gitignore` 影响，密钥会随源码一起被提交出去。
> 如果不慎提交过，请到服务商控制台吊销该密钥并重新生成。

### 配置生成模型（智能问答）

智能问答的检索部分（分块、向量化、混合召回）完全本地实现，**不依赖任何外部服务**；
只有最后的"作答"环节需要大模型。配置好后可运行自检确认：

```bash
python scripts/check_model.py
```

配置与自检都通过后，问答会由大模型归纳作答，并在回答中标注引用来源。
未配置或调用失败时，系统自动降级为**离线抽取式回答**（直接抽取原文要点 + 来源编号），
界面会明确提示当前处于降级状态 —— 这是刻意设计的降级路径，保证断网也能完整演示。

│           检索与 RAG 4 · 日志 2                          │

### 几处关键的技术取舍

- **全文检索用 MySQL 而非 Elasticsearch**：本课题数据规模为万级，MySQL 完全胜任；更重要的是索引与业务数据同库同事务，**不存在索引与主库不一致的时间窗口**，也省去了部署中间件的风险（答辩现场尤其重要）。中文用 `ngram` 解析器按二元切分，不依赖外部词典。
- **数据库只负责召回，排序交给应用层**：ngram 相关度天然偏好长文档，标题就叫《软件测试用例设计》的文档会被"关于检索技术的长报告"挤下去，于是先放大 6 倍取候选，再由应用层按「字段命中率 65% + 全文相关度 25% + 热度 10%」重新打分并本地分页。
- **向量存 `MEDIUMBLOB` + 内存余弦比对**：万级分块下暴力比对耗时约 30ms，引入向量数据库带来的运维成本大于收益。向量以 float32 小端序列存储，比 JSON 文本省约 4 倍空间。
- **RAG 必须能降级**：没有大模型 API Key 或调用失败时，自动切换为**离线抽取式回答** —— 直接抽取检索到的原文片段并按来源编号列出。它不是生成式回答，但零幻觉、可逐句核对，保证系统在任何环境下都能完整演示。
- **派生数据必须记录它的来源**：每个检索分块都记录 `embed_model` 与 `dim`。不同模型产出的向量不在同一向量空间，不能混合比较；切换模型后系统会提示存在"过期向量"并支持一键重建。

## 六、常见问题

**Q：检索不到内容？**
先确认后端已初始化完成（启动日志中应有「演示数据初始化完成」）。中文全文检索按二元切分建索引，**单个汉字的查询不会命中**，请使用两个及以上字符。

**Q：问答回答读起来像原文摘录，不像"说人话"？**
说明当前处于**离线抽取式**模式（未配置大模型或调用失败）。先运行自检脚本定位原因：

```bash
python scripts/check_model.py
```

它会打印当前生效的模型、可用状态，并实际发一次提问验证端到端链路。
配置方式：在 `backend/src/main/resources/application-local.yml` 中填写
`kms.rag.chat.openai` 的 `base-url` 与 `api-key`（任何 OpenAI 兼容服务均可：
DeepSeek、通义千问、智谱、Moonshot、本地 Ollama），重启即可。

**Q：如何换成真正的语义向量模型？**
修改 `kms.rag.embedding.provider` 为 `openai` 并填入 `api-key`，重启后在「检索索引」页点击**重建全部索引** —— 切换向量模型后必须重建，因为旧向量来自另一个向量空间。

**Q：日志里的中文是乱码？**
Windows 控制台默认代码页不是 UTF-8。启动脚本已加上 `-Dstdout.encoding=UTF-8`；若仍有问题，可先执行 `chcp 65001`。
