> **文档说明**
> 本文档是六份个人分工文档的总纲，给出分工原则、各模块边界、依赖关系与统一的
> 答辩口径。六份分册（01–06）都以下表为准，任何人在答辩中被问到"这块是谁做的"
> 时都能给出一致的答案。
>
> 代码量统计方式：后端为 `backend/src/main/java` 下的 Java 源码行数，
> 前端为 `frontend/src/views` 下对应页面的行数，文档为 `docs/` 下的 Markdown 行数。

## 一、分工原则

按**功能域**划分而不是按技术层次划分。常见做法是"一人做前端、一人做数据库、
其余做后端"，但这种划分有两个问题：一是每个人只接触系统的一个切面，
被问到业务细节时答不上来；二是模块边界与人的边界不一致，
出问题时难以定位责任人。

本组按功能域划分，每个成员完整负责一个功能域的**数据库设计、后端实现、
前端页面、测试用例与文档**，即"从表结构到界面"的纵向全栈。
这样每个人都能完整讲清自己那块"数据怎么存、逻辑怎么走、界面怎么用"。

## 三、模块依赖关系

依赖方向保持单向，不存在双向依赖，因此各模块可以独立开发与测试。

```
        成员1  数据库设计（schema.sql）
              │  提供全部表结构
    ┌─────────┼─────────┬─────────┬─────────┐
    ▼         ▼         ▼         ▼         ▼
  成员2     成员3     成员4     成员5     成员6
  知识库    附件/归档  本体     检索/版本   RAG
    │         │         │         │         │
    │         │         │         └────┬────┘
    │         │         ▼              │
    │         │      成员4 本体 ───────┘   成员6 调用本体的
    │         │      提供概念与关系        实体链接与查询扩展
    ▼         ▼
  成员3 复用成员2 的条目实体；成员6 监听成员2 的内容变更事件重建索引
```

关键接口有三处，答辩时容易被追问，需要三个人都能说清楚：

1. **成员2 ↔ 成员3**：成员3 的附件挂在成员2 的知识条目上（`kb_attachment.item_id`）。
   附件上传时抽取的正文会由成员2 拼接进条目的 `plain_text` 字段，从而进入检索范围。
2. **成员2 ↔ 成员6**：成员2 在条目保存/发布/回滚时发布 `ItemChangedEvent` 事件，
   成员6 异步监听并重建该条目的检索分块。两者通过事件解耦，成员2 不需要知道 RAG 的存在。
3. **成员4 ↔ 成员6**：成员6 在检索前调用成员4 的实体链接与概念扩展，
   把问题中的知识点沿本体关系扩展后拼入检索串。

## 四、统一的答辩口径

以下表述全组一致，避免不同人被问到时说法不一。

**关于技术选型。** 检索选择 MySQL 全文索引而不是 Elasticsearch，
理由有三条：数据规模在万级，MySQL 完全胜任；索引与业务数据同库同事务，
不存在主库与索引不一致的时间窗口；省去部署中间件的成本，
这对一次两周的课程设计而言是负收益。这个决策有明确的失效边界——
如果数据量增长到百万级，就应当换用专用检索组件。

**关于本体规模。** 任务书要求不少于 20 个知识点、5 种关系，
本系统实际实现 **107 个知识点、7 种关系类型、183 条关系实例**，
覆盖软件工程、数据库、知识管理三个知识域，本体覆盖率 93.46%。

**关于 RAG 的降级。** 未配置大模型接口时，系统自动切换为离线抽取式回答：
直接抽取检索到的原文要点并按来源编号列出。这不是"聊胜于无"的兜底，
而是刻意设计的降级路径——它零幻觉、可逐句核对，断网也能完整演示。

**关于已完成的测试。** 两套可重复执行的自动化脚本：
接口测试 78 项断言、界面测试 38 项断言，覆盖 15 个页面，全部通过。
脚本会生成截图，因此截图存在本身即意味着该页面通过了检查。

**关于系统规模。** 60 条知识条目、107 个知识点、183 条关系、11 个附件、
164 个检索分块、20 张数据库表、98 个 Java 源文件、26 个 Vue 组件。

## 六、答辩演示分工建议

演示环节建议按"系统全流程"而不是按模块顺序走，这样听者看到的是一个连贯的系统。

| 顺序 | 演示内容 | 主讲 | 时长 |
|---|---|---|---|
| 1 | 登录与角色权限、首页看板 | 成员 1 | 1.5 min |
| 2 | 知识库浏览、分类与标签筛选、打开一篇带附件的文档 | 成员 2 | 2 min |
| 3 | 新建知识、上传 PDF 与图片、查看附件正文抽取结果 | 成员 3 | 2 min |
| 4 | 知识图谱、点击节点看关系、学习路径推理 | 成员 4 | 2.5 min |
| 5 | 高级检索、讲排序依据；版本历史与差异比对 | 成员 5 | 3 min |
| 6 | 智能问答、展开检索过程、核对引用来源 | 成员 6 | 3 min |
| — | 提问答疑 | 全员 | 5 min |

> 每人只需讲自己那段，但**要能回答相邻模块的提问**——因此建议每人在答辩前
> 至少把相邻那位的分册读一遍。
